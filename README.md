# アイカツDCB V0.1

スマートフォンでカード収集の操作感を試す、非公式・個人利用のフロントエンド試作です。番号OCRにTesseract.jsを使用します。バックエンド、外部OCR API接続はありません。

## 起動

JSONの読み込みにはHTTP配信が必要です。Node.jsで `npm start` を実行し、 http://localhost:4173 を開く方法です。初回は `npm ci` を実行してください。

スマートフォンのカメラ確認にはVercel等のHTTPS URLを使います。LANのHTTPではカメラを使用できません。サーバーは試作確認用です。終了は Ctrl+C。

## 操作

オープニング → デモログイン → ホーム → バインダー → コーデ → カード詳細。カード番号・名前・ブランド・キャラクターの検索、8項目の絞り込み、所持状態別表示が使えます。下部ナビとブラウザの戻る操作で移動できます。

カード詳細で所持枚数・交換候補枚数・お気に入り・メモを自動保存します。交換候補は設定した保管枚数を残した余剰分のみ、各リストは最大50種類。所持枚数は0〜999。データはlocalStorageでブラウザ・アクセス先ごとに保存されます。file版、localhost版、スマホ版のデータは独立します。バックアップ・復元は未実装です。保存失敗は表示します。

## 仮仕様と今後

カードMasterはverified版Excelの全カード139件を使用します。未確認の表記はそのまま保持します。画像はタイプ別のSVGトークンと登録写真を基本にし、公式画像URLは参照情報として保持します。Master更新はExcelの編集と再変換で行います。収集率は所持種類数÷Master全種類、最近登録は所持カードの最終編集順（初期値はデータ順）です。ログインはメールアドレスまたはコレクターID・パスワードを入力するUI試作で、アクセス制御はありません。入力したIDから表示名を設定します。毎回の初期URLでロード画面・ログインを表示します。

トレードは端末内リストとダミーQRのデモ読み取りによる照合まで実装しています。ニュースは試作用データです。正式認証・クラウド・課金・同期・実QR生成／復号・画像認識は未実装。番号OCRはTesseract.jsで実装済みです。PWAは公開ビルドにmanifestとアイコンを用意しています（オフライン対応は未実装）。公式画像やスクレイピングは使っていません。モックアップ2枚は添付に存在しなかったため、制作要件の配色と情報設計を基準にしています。

次の改善は、実機での情報量・操作性確認、実カードマスターの項目確定、写真のバックアップ・データ復元、実QR通信と実機での読み取り検証です。

起動URLなし・ホーム・ログイン・#openingからはロード後にログインへ進みます。カード詳細等の直接URLは、編集・再読み込みの利便性のため遷移先を維持します。正式な独自ロゴへの差し替えはapp.jsのopening-logoの内容を置き換えます。

## ログイン画面更新

白背景・ピンクのロゴ・同じCSSの星1つでオープニングの構成を継承。ID、パスワード、ログインボタン、ログイン維持チェック、パスワード再設定リンクのみにしています。PCもオープニングと同じ390px幅です。
ログインは任意の仮IDと仮パスワードでホームへ進むデモです。パスワードは保存・送信しません。「ログインしたままにする」はV0.1ではチェック状態とID入力の保持のみで、自動認証はしません。再設定リンクは未実装で、クリック時にその旨を表示します。

## ホーム画面の簡素化

ホームは白＋明るいピンクで、ロゴ・最新ニュース3件・総登録数/収集率/最近の記録・バインダーを開く・下部ナビに整理しました。大きな収集率カード、お気に入り/完成コーデの情報ブロック、カードサムネイル、英文コピー、ユーザーアイコン、ホームのフッターを省略しています。
ニュースはdata.jsの試作用データで、行から記事へ、もっと見るから一覧へ移動できます。総登録数は所持しているカードの種類数（枚数の合計ではありません）、最近の記録は所持カードの最終編集番号です。記録がなければ「—」を表示します。

## カード番号による登録フロー

バインダーの「＋ カード登録」から開始します。初期は確認登録で、カメラ番号OCRまたは手入力→Master照合→該当カード→全体撮影→所持枚数＋1→次の番号です。高速登録では、完全一致で所持枚数＋1に進み、撮影を省略します。上部トグルまたは設定画面で切り替えられます。終了を選ぶとバインダーに戻ります。

カメラは「カメラを起動」で背面カメラ優先のプレビューを開きます。ブラウザの許可が必要です。カメラを使えない場合もデモで全フローを確認できます。番号ガイドの映像を実OCRし、複数フレームのMaster候補を集計します。カード画像からのAI推定は行いません。

- 一致：E1-04等のMaster番号を照合
- 誤読：E1-O4等をMaster補正候補へ変換して票を集計
- 同一番号：通常版／パラレル等を確認して選択
- 不明瞭／Master外：再読み取り・手入力

Masterの内部IDと仕様別管理を維持します。同じ番号が複数ある場合は高速モードでも自動確定しません。
確認登録の「撮影して登録」はガイド枠内をJPEGに切り出します。カメラ未起動ならダミー画像を撮影します。「自動撮影を試す」は1秒の安定待ちを疑似再現するボタンで、四隅検出は未実装です。「写真なしで登録」も使えます。

撮影写真は端末内IndexedDBに、所持枚数は既存localStorageに保存します。同じカードの写真は最新1枚に置き換えます。写真はカード詳細に表示し、再読み込み後も保持します。写真保存または所持保存が失敗すると成功扱いにせず、写真変更は可能な範囲で元に戻します。連打中は読み取り/登録をロックします。カメラは登録終了・他画面への移動・バックグラウンド移行時に停止します。

写真は同じブラウザとアクセス先のみで利用できます。JSON書き出しには写真を含みません。クラウド同期、写真バックアップ、AI補助、四隅検出は未実装です。

## カード入手ニュース

アプリ開発のお知らせをカード入手情報のダミー4件に差し替えました。ホームは最新3件、もっと見るでは全4件を表示します。表示は分類ラベル＋タイトルのみで、日時は表示しません。dateは並び順のためだけに保持しています。
分類はdata.jsのnewsCategoriesでゲーム（#ff62a7）・配布（#298dde）・付録（#eb891f）・特典（#a563d8）に固定。newsのacquisitionTypeからラベルと色を取得し、白背景のラベル文字・枠だけを色分けします。掲載内容はすべてUI確認用の架空情報で、実際の配布・販売情報ではありません。

styles.cssの:rootで--color-primary、--color-blue、--color-orange、--color-purple、--color-background、--color-border、--color-text等を一元管理します。ニュースの分類色も同じCSS変数を参照します。カードの仮画像に使うブランド色はカードデータとして維持しています。

ホームを「最新カードニュース」「バインダー＋カード登録」「トレード／交換候補」の3つの入口に整理しました。ニュースはホーム内だけ高さ40px（小型スマホ38px）へ縮小し、最新3件と分類色を維持しています。バインダー見出し横は「バインダーを開く」、その下のPrimaryは「＋ カード登録」です。ホームの「交換候補を見る」は#trade/offersの専用リストへ移動します。下部ナビのトレードは独立した#tradeを維持します。


## トレード V0.1

`#trade` は上から横並びの「QRを読み取る／QRを表示」、1行の実物確認文、「交換に出せるカード」「ほしいカード」の構成です。各セクションは見出し右側に「すべて」と登録数、下に5種類のレア度チップ、横並びの「カードを見る／＋追加する」を表示します。「すべて」と個別チップは排他的に選択します。320×568でも主要操作はスクロールなしで収まります。QR操作は共有btn-tile修飾（112px角）、通常の管理ボタンは共有44px高、レア度チップは共有32px高です。ボタンは既存のbuttons.cssのPrimary／Secondary／Textを使用します。

交換候補はstore.jsのtradeCountと連携します。最低1枚を残し、追加可能数は `ownedCount - retainCount - tradeCount`。retainCountは将来の保持枚数設定用です。種類上限は各50種類で、同じ種類への枚数追加は余剰の範囲内で可能です。所持枚数が減ると交換可能枚数も減ります。旧データで手元の1枚まで交換候補になっていた場合も、読み込み時に余剰範囲へ補正します。

ほしいカードは `dcb-trade-wants-v01` にカードIDを保存します。追加一覧は未所持を先に並べ、所持済みカードも登録できます。両リストは番号と画像中心の専用一覧です。交換候補のバッジは所持枚数ではなく交換枚数です。

QR表示：トレードページ内で、出せるカード・ほしいカードのレア度を独立して複数選択→「QRを表示」→即QR表示。有効な交換候補またはほしいカードが選択中のレア度に1種類以上該当するときだけ有効化し、両方0種類の場合はグレーで無効にします。条件選択・確認の中間画面はありません。チップは「すべて／パラレル／プレミアム／アンコール／レア／ノーマル」。すべては制限なしを表し、既存サンプルのPRはプレミアム、Rはレアに対応します。分類はtrade-model.jsのrarityTypesで管理し、将来のMasterではtradeRarityへ分類IDを指定できます。ダミーQRの模様は実際のQRとして復号できません。QR表示画面はQR・期限・出せる種類数・ほしい種類数・戻るだけを表示します。内部JSONの表示・コピー・貼り付け操作はユーザー向け画面から削除しました。「ダミーQRを読み込む」は現在の自分のリストに対応する架空の相手データをメモリ内で作ります。

ペイロードはprotocol／version／sessionId／nonce／createdAt／expiresAt／rarities（旧形式との互換用）／filters（offers・wantsの独立条件）／offers（ID・枚数）／wants（ID・希望枚数）だけです。有効期限は15分。本名・メールアドレス等は含めません。読み込み時に形式・版・期限・カードID・重複・枚数・50種類上限を確認します。相手情報と生成セッションはメモリ内だけで、リロード時に破棄します。暗号化・署名・使用済みセッション管理は本番化時の課題です。

照合は「自分が出せる×相手がほしい」と「相手が出せる×自分がほしい」の両方向。レア度は対象整理にのみ使い、交換価値や公平性は判定しません。「確認を終える」は双方の実物確認チェック後に戻るUIで、所持枚数を自動増減する処理は行いません。読み取りボタンはカメラアイコンを使用し、#trade/scanへ移動すると自動起動します。権限拒否・未対応時は再試行またはデモ読み取りを利用できます。カメラはプレビューまでで、実際のQR復号は未実装。画面移動・非表示時には停止します。

追加ファイル：trade-model.js（上限・余剰・セッション・照合）、trade.js（画面と操作）、test-trade.cjs（ロジック）、verify-trade.cjs（ブラウザ検証）。`npm test` に上限・保存失敗・期限・照合の検証を追加しました。

## 設定

設定トップはユーザー情報・カード登録・表示設定・バックアップ（開発中）・アイカツDCBについての一覧です。バックアップは操作できません。各詳細ページには戻るボタンがあります。アプリ情報の収録枚数はMasterのカード件数から取得し、利用規約は準備中です。

ユーザーIDとメールアドレスは端末内に保存します。メール変更・パスワード変更は認証サーバーを使わないデモです。現在のパスワードはこのページで最後にログインした入力と照合します。パスワードは保存・送信せず、再読み込み後の変更にはログインし直す必要があります。

カード登録設定では確認登録／高速登録と、各1〜5枚の保管枚数一括変更ができます。一括変更は全カードに適用し、交換候補枚数を余剰分以内に調整します。カード詳細の保管枚数は個別に変更でき、次の一括変更まで維持します。将来追加されるMasterカードにも一括設定を基本値として使用します。

表示設定（#settings/display）ではキュート／クール／セクシー／ポップのメインカラー、ホワイト／ダークのテーマ、日本語を個別に選択できます。`display.js`が`dcb-display-v01`へ保存し、初期描画前に適用します。`theme.css`は操作UIの色・背景・文字・境界線を管理し、カード画像とニュース分類色、コーデのタイプ色は固定です。対応言語は`DCBDisplay.languages`で管理し、翻訳実装時に追加できます。英語翻訳は未実装です。
